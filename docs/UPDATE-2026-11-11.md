### 1. 首页加载慢 → 加 gzip（`server.js`）

- **症状**：打开控制台要 2 秒以上，感觉服务器卡。
- **真因**：不是性能问题（实测 CPU 0.3%、`/api/state` 响应 0.4ms），是 `index.html` 有 205KB 且**没开压缩**，公网传输慢。
- **修法**：`serveStatic()` 对 `text/*`、`application/(json|javascript|xml)`、`image/svg` 且 >1KB 的文件自动 gzip；首次压缩后缓存在内存（key = mtime + size，**文件改了自动失效**，不用手动清缓存）；响应头带 `vary: Accept-Encoding`，不支持的客户端自动回退明文。

**实测**：`205,549 B → 60,410 B`，首页总耗时 `2.43s → 0.095s`（约 25 倍）。

> 前面已有 Nginx 的话保留它也没问题（不冲突），想省一层 CPU 也可以关掉 Nginx 的 gzip。

### 2. 新增：签到里程碑自动兑换（`lib/streakredeem.js`）

**这是签到体系的延伸，不是成长任务。** 三档奖励：

| 档位 | 门槛 | 奖励 |
|---|---|---|
| 入门档 | 连续签到 7 天 | 2 能量 + 1 补登卡 + 1 抽奖 |
| 进阶档 | 连续签到 14 天 | 50 积分 + 3 能量 + 1 补登卡 + 1 抽奖 |
| 巅峰档 | 连续签到 28 天 | 150 积分 + 5 能量 + 1 补登卡 + 1 抽奖 |

**运行方式（不是每天扫）**：

- **默认每周巡检一次**（`intervalMinutes = 10080`）；
- 同时记录每个号的 `nextEligibleAt`（按当前连续天数推算还差几天到下一档），**到点的那一轮提前触发**，不必干等满一周；
- 只在档位状态为 `available` 时才兑换，兑完**立刻把拿到的抽奖机会抽掉**；
- 有补登卡 + 本月有漏签 → 自动补**最近一次**漏签。

配置（`settings.streakRedeem`）：

```js
{
  enabled: true,
  intervalMinutes: 10080,   // 每周一次
  autoLottery: true,        // 兑换后自动抽奖
  autoMakeup: true          // 自动补最近一次漏签
}
```

**接口契约（踩过的坑）**：

```
POST /activity/growth/redeem
body: { tier: "7d"|"14d"|"28d", client_token: "<随机串>" }
```

- `client_token` **不能省**。只传 `tier` 会一直返回 `400 invalid redemption request`；
- 它是幂等键，同一次兑换重试要复用同一个 token；
- 返回语义：`409` + msg 含 `duplicate` = 幂等命中（其实已成功）；`409` = 本月已领；`403` = 连续天数不够。

> ⚠️ 实现时**不能用 `interpret()`** 解析 —— 它对 401/403 会直接抛异常，而这里的 403 是「天数不够」的正常业务分支。本改动已改用 `res.json` 自行判断。

### 3. 新增：`lib/wb.js` 的 4 个方法

```js
const wb = require('./lib/wb');

await wb.redeemTier(acc, '7d');            // 兑换（client_token 自动生成）
await wb.redeemSummary(acc);               // 查本月兑换情况
await wb.useMakeupCard(acc, '2026-11-03'); // 用补登卡补某天
await wb.lotteryDraw(acc);                 // 抽奖一次
```

### 4. 保活：每天发一句轻量对话（`lib/keepalive.js`）

`reportActive()` 原来是空实现（上游确实没有心跳/在线接口，4 个常见命名全 404）。现在改为每天发一句最小对话：

- 用途：让账号保有真实调用记录，避免长期零流量的"死号"特征；
- 幂等：按北京时间自然日记录，同一天只发一次；
- 开关：`settings.keepalive.dailyChat`（默认 `true`），文案可改 `dailyChatPrompt`。

> ⚠️ **它不能点亮成长热力图，也不能修复 streak 断签。**
> 实测对某账号连发 2 次对话（均 200），100 秒内 `heatmap score` 恒为 0。
> 热力图 / 连续天数由**桌面客户端本地埋点**驱动，服务端 API 伪造不出来。

### 新增：分享技能埋点（`lib/wbreport.js`）

新增 `skillShareSequence(skill, conv, req, channel)`，按官方客户端构造四个事件：
`skill_share_entry_click` → `skill_share_security_result` → `skill_share_channel_action` → `skill_share_conversion`

> **实测结论（务必知道）**：这四个事件上报都返回 200，但**不增加 `skill_share` 任务的进度**，
> `claim` 仍返回 `task not completed`。
>
> 原因已查明：分享走的是 **Electron IPC + 网盘**，不是 HTTP 接口：
> `getNetDriveAccessToken({projectId, scope:'all'})` → `resolveProjectNetdriveRoot()` 取 rootFolderId
> → `skillC2CShareCreate()` 上传技能包 → `skillC2CShareResolve()` / `skillC2CShareDownloadUrl()`。
> 需要网盘授权 + 本地技能包文件，纯服务端伪造不了。
>
> 所以该方法**留着供后续验证，不要指望它能自动完成该任务**。
