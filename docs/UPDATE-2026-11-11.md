## 二、逐条说明

### 1. 首页加载慢 → 加 gzip（最值得更新的一条）

**症状**：控制台打开要 2 秒以上，感觉"服务器卡"。
**真因**：不是服务器性能问题（实测 CPU 0.3%、接口 0.4ms），是 `index.html` 205KB **没开压缩**，走公网传输慢。

`server.js` 的 `serveStatic()` 现在会：
- 对 `text/*`、`application/(json|javascript|xml)`、`image/svg` 且 >1KB 的文件自动 gzip；
- 首次压缩后缓存在内存（key = mtime + size，**改了文件自动失效**，不用手动清缓存）；
- 请求头带 `vary: Accept-Encoding`，不支持的客户端自动回退明文。

实测：`205,549 B → 60,410 B`，总耗时 `2.43s → 0.095s`。

> 如果你的服务前面已经有 Nginx，可以二选一：要么保留 Nginx 的 gzip、把本改动当兜底（不冲突，Nginx 已压缩的不会再压一次），要么直接用本改动、把 Nginx 的 gzip 关掉省一层 CPU。

### 2. 成长任务：新增兑换 / 补登 / 抽奖能力（`lib/wb.js`）

之前只能读连续签到状态，不能操作。本次补上了官方接口：

```js
const wb = require('./lib/wb');

// 兑换里程碑（7d / 14d / 28d）
await wb.redeemTier(acc, '7d');            // client_token 会自动生成

// 查本月兑换情况
await wb.redeemSummary(acc);

// 用补登卡补某天
await wb.useMakeupCard(acc, '2026-11-03');

// 抽奖一次
await wb.lotteryDraw(acc);
```

**接口契约（踩坑记录）**：
```
POST /activity/growth/redeem
body: { tier: "7d"|"14d"|"28d", client_token: "<随机串>" }
```
- `client_token` **不能省**，只传 `tier` 会一直返回 `400 invalid redemption request`；
- 它是幂等键，同一次兑换重试要复用同一个 token；
- 返回语义：`409 + msg 含 duplicate` = 幂等命中（其实是成功）；`409` = 本月已领；`403` = 连续天数不够。

**三档奖励**：7 天 = 2 能量 + 1 补登卡 + 1 抽奖；14 天 = 50 积分 + 3 能量 + 1 补登卡 + 1 抽奖；28 天 = 150 积分 + 5 能量 + 1 补登卡 + 1 抽奖。

> ⚠️ 实现时**不能用 `interpret()`** 解析响应 —— 它对 401/403 会直接抛异常，而这里的 403 是「天数不够」的正常业务分支。本改动已改用 `res.json` 自行判断。

### 3. 分享技能埋点（`lib/wbreport.js`）

新增 `skillShareSequence(skill, conversationId, requestId, channel)`，按官方客户端四个事件构造：

```
skill_share_entry_click → skill_share_security_result
                       → skill_share_channel_action → skill_share_conversion
```

> **重要提醒**：实测这四个事件上报都返回 200，但**不增加 `skill_share` 任务的进度**，
> 服务端 `claim` 仍返回 `task not completed`。
> 该任务大概率需要「分享链接真实被另一台设备打开」这类业务事件，纯埋点伪造不了。
> 这个方法留着是为了后续验证，**不要指望它能自动完成该任务**。

### 4. 保活：每天发一句轻量对话（`lib/keepalive.js`）

原来 `reportActive()` 是空实现（上游确实没有心跳/在线接口，4 个常见命名全 404）。现在改为**每天发一句最小对话**：

- 用途：让账号保有真实调用记录，避免长期零流量的"死号"特征；顺带给「每天有对话」类任务提供真实计数；
- 幂等：按北京时间自然日记录，同一天只发一次；
- 开关：`settings.keepalive.dailyChat`（默认 `true`），文案可改 `dailyChatPrompt`。

> ⚠️ **它不能点亮成长热力图，也不能修复 streak 断签。**
> 实测对某账号连发 2 次对话（均 200），100 秒内 `heatmap score` 恒为 0。
> 热力图/连续天数由**桌面客户端本地埋点**驱动，服务端 API 伪造不出来。
> 别指望靠它刷连续打卡天数。
